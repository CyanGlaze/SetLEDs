# 2026-10-18

- 用户需求：黑苹果(macOS 26, 联想 Legion, ITE 8910 EC)上让物理 NumLock 键切换小键盘（此前只能手动 `sudo setleds +num`）。
- 关键发现：
  - /Library/LaunchDaemons/com.rajiteh.setleds.plist（xiaoMGit Y7000 NumLockFix）内容是 gitee 302 跳转 HTML，非 XML，从未加载过 → 之前的"修复"实际无效。
  - 上午构建的 numlockd（用户级 LaunchAgent 方案）未安装未运行（~/Library/LaunchAgents 无 plist）。
  - 普通用户打开 HID 全部失败 0xe00002e2（TCC），必须 root 或授权。
  - ITE Device(8910) 顶层 collection 是 vendor-defined(0xFF79)，键盘 usage 匹配看不到它；NumLock 键事件(usage 0x53)只从 ITE 设备发出。LED 写入走 'Keyboard'(05ac:ffff, usage 1/6) 即可生效（setleds +num 已验证）。
- 改动：main.c 加 -d/--daemon 守护模式（监听全部 HID 设备的 0x53 按键 → 复用 setAllKeyboards 的 ^num Toggle 路径写 LED；支持 +num/-num 设定初始状态、250ms 防抖、设备迟到的强制状态）；install.sh/uninstall.sh 重写为 root LaunchDaemon（com.setleds.numlockd, /usr/local/bin/setleds -d +num, 日志 /var/log/setleds.log, 免 TCC）；顺带清理损坏的 rajiteh plist。
- 状态：编译验证通过；安装需用户输密码执行 ./install.sh，装完按 NumLock 测试。若 root daemon 收不到按键（macOS 26 风险），回退方案是用户级 LaunchAgent + 输入监控授权（旧 install.sh 思路）。

## 14:04 第三轮（root daemon 失败，改用户代理）
- 用户跑 install.sh（root LaunchDaemon 方案）：守护进程以 root 运行仍被拒 0xe00002e2 → **macOS 26 上系统域守护进程没有 GUI 会话，即使 root 也无法打开 HID**（之前 install.sh 里"root 免 TCC"的假设被实测推翻）。而终端里 sudo 能成功，因为终端进程在用户 GUI 会话内。
- 方案改为：用户级 LaunchAgent（gui 域，登录自启）+ 系统设置一次性授予"输入监控"。install.sh 重写：编译时嵌入 Info.plist（com.setleds.numlockd，TCC 列表显示 "NumLock daemon"）+ adhoc 签名；安装到 ~/Library/Application Support/setleds/setleds；日志 ~/Library/Logs/setleds.log；自动打开输入监控设置面板并 reveal 二进制；授权后 kickstart 并检查日志判断是否生效。
- Info.plist 从 archive-doubao/ 恢复回项目根目录（编译需要）。
- 注意：重建/重装二进制后 CDHash 变化，输入监控授权可能需重新勾选；守护进程运行时不要同时前台 sudo setleds -d。
- 状态：脚本已就绪并验证编译/签名；等用户跑 ./install.sh → 授权 → 按 NumLock 测试。
- **14:28 用户确认：用户级 LaunchAgent + 输入监控授权方案成功，NumLock 可切换小键盘，任务完成。** 用户同时说明旧豆包方案是放 /usr/bin + 开"辅助功能"，与最终方案（~/Library/Application Support/setleds + "输入监控"）不同。
